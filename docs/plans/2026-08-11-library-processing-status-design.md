# 最近档案处理状态同步设计

## 背景

用户从工作台发起“生成转写稿”后，系统会先生成转写稿，再自动生成总结。当前这两个任务只存在于工作台的前端任务状态中，而最近档案只读取后端返回的持久化字段，导致任务运行期间仍显示“需转写”。

## 产品决定

最近档案不暴露“转写中”和“总结中”两个内部阶段，统一显示“处理中”。状态生命周期为：

`需转写 -> 处理中 -> 已总结`

- 用户确认转写设置并真正启动任务后，目标档案立即显示“处理中”。
- 转写完成但自动总结尚未完成时，继续显示“处理中”。
- 自动总结成功后，刷新档案数据并显示持久化结果“已总结”或“基础摘要”。
- 转写或总结失败时退出“处理中”，恢复档案真实状态；详细错误继续由现有任务提示负责。
- 不新增“处理中”筛选项。处理中档案仍保留在它原来的业务筛选范围内，避免为短暂状态增加入口。

## 状态归属

后端档案字段仍是完成结果的唯一权威来源。前端新增一个按 `video_id` 识别的短期处理标记，只用于覆盖任务运行期间的展示状态。

- `RecentLibrary` 接收正在处理的档案 ID 集合。
- 行状态的优先级为：正在打开档案 > 正在处理 > 持久化档案状态。
- 转写任务和自动总结任务继续使用现有 Hook，不复制请求逻辑。
- 处理标记在当前浏览器标签页的会话存储中保留，使页面内返回、浏览器前进后退和刷新后仍可恢复。

## 刷新恢复

当前标签页刷新后，前端读取尚未过期的处理标记并核对档案详情：

1. 档案已经有总结结果时，清除标记并显示完成状态。
2. 档案已有转写稿但总结尚未生成时，恢复自动总结。
3. 档案仍没有转写稿时，按现有转写恢复节奏轮询档案结果；转写出现后继续自动总结。
4. 标记超过现有 30 分钟恢复时限，或恢复过程确认失败时，清除标记并恢复真实档案状态。

会话存储不跨浏览器标签页或浏览器重启，避免旧任务在未来会话中形成无法确认的假“处理中”。

## 删除与清空

删除单条档案时同步删除该档案的处理标记；清空全部档案时清空全部处理标记。任务请求本身沿用现有行为，不借由列表操作伪造取消能力。

## 验证

- 转写请求运行时返回主页，目标档案显示“处理中”。
- 转写完成、自动总结运行时，仍显示“处理中”。
- 总结完成并刷新档案后，显示“已总结”或“基础摘要”。
- 当前标签页刷新后可以恢复处理状态，并在转写已完成时继续总结。
- 其他档案不受目标任务影响。
- 失败、超时、删除和清空不会留下永久“处理中”。

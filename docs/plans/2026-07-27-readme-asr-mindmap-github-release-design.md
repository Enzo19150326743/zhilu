# README ASR、思维导图与 GitHub 发布设计

## 目标

把当前会话中已经完成并验证的本地 ASR 与思维导图能力准确写入公开 README，随后将完整提交历史发布到 GitHub 默认分支。

## README 信息结构

- 保留现有产品定位、安装方式和本地优先说明，不做与本次功能无关的大改版。
- 在核心能力区明确 SenseVoiceSmall、Whisper 与 Fun-ASR-Flash 的角色，避免把三个入口描述成没有优先级的平行选项。
- 增加简洁的模型选型表：SenseVoiceSmall 作为中文长内容推荐默认项，Whisper 用于英文术语、数字与技术内容，云端模型只在用户手动选择后启用。
- 增加思维导图说明：按内容类型组织 4–7 个主分支，默认展开到第三级，并支持缩放、适应画布、重置、拖拽平移、节点高亮与子树展开收起。
- 修正仍将 SenseVoiceSmall 称为“实验能力”的旧文案，并补充 CUDA 与 CPU 回退边界。

## 图片策略

- 优先使用真实本地页面生成公开安全截图，不制作与实际产品不一致的概念图。
- 截图不得包含 API Key、Cookie、本地绝对路径或私人媒体历史。
- 图片保持浏览器原始宽高比；README 使用 Markdown 自适应宽度，不设置会导致拉伸的固定宽高组合。
- 如果无法在不暴露本地数据的情况下稳定取得导图截图，则只更新文字和表格，不放置虚假占位图。

## Git 发布策略

- 当前功能分支 `experiment/sensevoice-small-eval` 包含本轮完整提交链。
- README 更新、图片与验证结果先提交到当前功能分支。
- 获取远程最新状态后，将本地 `main` 以 `--ff-only` 快进到功能分支，避免改写历史。
- 推送 `main` 到 `origin`；功能分支与本地回滚分支不强制推送。

## 验证

- 检查 README 中的相对链接与图片文件是否存在。
- 使用图片工具核对新增截图的像素尺寸与视觉内容，避免截断和非等比例拉伸。
- 执行前端辅助测试、生产构建、后端完整测试和公开发布检查。
- 推送后核对本地 `main`、`origin/main` 与目标提交一致，且工作区干净。

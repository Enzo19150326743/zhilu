# 小红书封面、转写链路与统一空状态设计

> **日期**：2026-08-11  
> **状态**：已确认，进入实施

## 一、目标

修复小红书封面色块化、点击“生成转写稿”无响应的问题，并统一总结、思维导图、内容问答、内容文本四个模块在缺少完整逐字稿时的操作入口。

完成后的用户路径是：打开一条尚无逐字稿的媒体档案，在任意知识稿模块看到同一套空状态，点击“生成转写稿”，通过唯一的转写设置弹窗确认后开始任务。

## 二、根因

### 1. 封面色块化

小红书公开页面同时提供 `WB_PRV/urlPre` 预览图和 `WB_DFT/urlDefault` 默认图。当前 yt-dlp 结果选择了 `PRV` 图，该资源本身就是低细节、色块化预览，不是 CSS 模糊层覆盖前景造成的。

### 2. 点击转写无响应

小红书无字幕记录仍带有“未检测到可用 VTT/SRT 字幕。”占位文本。工作台按钮显示条件使用 `video.has_transcript`，点击处理函数却只判断 `transcript.plain_text` 是否非空，两个状态源冲突，导致处理函数静默返回。

### 3. 小红书缺少稳定转写源

小红书页面初始状态中存在可访问的带音频 MP4 `masterUrl`，当前解析响应没有写入 `transcription_source_url`。转写时因此重新把页面 URL 交给通用下载器，无法复用已经解析出的稳定媒体流。

### 4. 转写入口重复

内容文本页维护局部 `transcribeSettings` 和行内 `TranscribeSettingsPanel`，其他模块则打开全局 `TranscribeSettingsDialog`。同一个转写任务拥有两套设置入口和不同空状态样式。

## 三、产品与交互决策

1. 视频封面继续使用固定 4:3 画布，工作台桌面左栏保持约 300×225px；窄屏继续限制最大宽度。
2. 前景使用清晰的 `WB_DFT/urlDefault` 图片和 `object-contain`，不裁切、不拉伸。
3. 比例不一致时，继续用同一清晰图片的低透明度模糊副本填充上下或左右区域；背景层必须位于前景之后，不能改变前景颜色。
4. 总结、思维导图、内容问答、内容文本缺少完整逐字稿时，共用一个转写空状态组件和同一个“生成转写稿”动作。
5. 页面不直接铺开转写设置。点击“生成转写稿”统一打开现有 `TranscribeSettingsDialog`；“开始转写”是该弹窗唯一提交动作。
6. 前端判断已有逐字稿时，以 `video.has_transcript` 与真实文本共同成立为准，占位文字不构成逐字稿。

## 四、后端数据流

```text
POST /api/parse
→ XiaohongshuVideoSourceAdapter
→ yt-dlp 获取基础元数据
→ 读取公开页面 INITIAL_STATE
→ 使用 imageList.urlDefault / WB_DFT 覆盖预览封面
→ 从 video.media.stream 选择带音频的公开 MP4 masterUrl
→ 写入 transcription_source_url

POST /api/transcribe
→ 识别小红书 URL
→ 重新解析页面，刷新可能过期的签名媒体 URL
→ 将 transcription_source_url 交给现有 SenseVoice / Whisper
→ 结果继续写回同一条本地档案
```

作者、清晰封面和转写源属于同一次公开页面读取结果。辅助字段解析失败时保留基础元数据，但转写动作必须返回可见错误，不能静默无响应。

## 五、组件边界

- `xiaohongshu_service.py`：负责小红书公开页面字段提取与 ParseResponse 补齐。
- `main.py::_resolve_transcription_source`：负责在转写前刷新平台媒体源。
- `use-transcribe-workflow.ts`：负责统一打开设置弹窗和启动任务，不再使用占位文本判断完成状态。
- 新的共享转写空状态组件：负责四个知识稿模块中一致的状态、说明和操作。
- `TranscriptTab.tsx`：删除局部转写设置状态和行内设置面板。

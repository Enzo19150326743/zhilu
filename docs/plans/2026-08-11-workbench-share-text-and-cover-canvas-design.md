# 工作台分享文案输入与封面画布设计

> **状态**：已批准  
> **决策日期**：2026-08-11

## 一、目标

修复工作台内部无法提交整段平台分享文案的问题，并让不同横竖比例的视频封面在工作台保持稳定、克制的视觉占比，同时不裁掉人物、标题文字等识别信息。

## 二、问题根因

### 工作台输入

首页和工作台共用同一解析控制器，后端也已经通过 `extract_public_url()` 支持从整段分享文案中提取第一个公开 URL。问题发生在请求之前：工作台把输入框放在表单中，并使用 `type="url"`。整段分享文案不符合浏览器原生 URL 校验，因此提交事件被浏览器拦截；首页按钮使用 `type="button"`，没有触发这层原生校验，所以相同文案能够解析。

### 封面尺寸

普通视频封面当前使用 `width: 100%`、`height: auto` 和 `object-contain`，外层没有固定比例。结果是原图比例直接决定工作台左栏高度，竖版小红书或抖音封面会占据过大空间。

## 三、方案与决策

封面方案比较：

1. 保持原始比例：信息完整，但不同内容切换时左栏高度跳变，不采用。
2. 固定画布并使用 `object-cover`：尺寸稳定，但会裁掉人物和封面文字，不采用。
3. 固定画布并使用 `object-contain`：尺寸稳定且保留完整封面，采用。

## 四、交互与空间结构

- 首页和工作台输入框都按“公开链接或整段分享文案”处理，使用普通文本输入语义并保留 `inputMode="url"`；URL 提取仍由后端统一负责，前端不复制一套解析规则。
- 视频封面使用固定 4:3 画布。桌面左栏宽度为 300px，因此画布实际约为 300×225px；单栏视口下预览卡最大宽度为 420px，避免平板宽度下封面过度放大。
- 原封面作为前景完整等比缩放并居中；同一张图的模糊低对比背景填满画布空白，不使用硬裁切。
- 播客封面继续保持方形，因为方形是播客封面的稳定内容约定；视频与播客不强行使用同一比例。
- 加载失败兜底与成功画布使用相同比例，避免图片失败时布局跳动。

## 五、数据流与错误处理

```text
公开 URL 或整段分享文案
→ 前端保留原输入并提交
→ POST /api/parse
→ 后端 extract_public_url() 提取第一个 URL
→ 平台 Adapter 解析
→ 返回工作台详情
```

输入没有任何公开 URL 时，继续使用现有后端结构化错误；请求失败时保留用户输入，不清空工作台。封面加载失败时继续显示固定画布兜底，不影响标题、作者、平台和后续操作。

## 六、验证

- 增加工作台回归测试：输入包含文字和小红书 URL 的完整分享文案，点击“提取内容”后请求能够发出，不出现浏览器“请输入 URL”拦截。
- 检查首页和工作台输入框使用一致语义。
- 增加封面画布断言：桌面 300px 左栏下视频画布约 300×225px，且前景使用完整缩放。
- 通过实际工作台截图检查封面没有压过右侧主内容，也没有小到失去识别作用。
- 运行前端 helper 测试、相关 Playwright 测试和生产构建。
